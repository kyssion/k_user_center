# .NET 业务规则与状态机实现清单

## 1. 每个写命令的统一管线

所有领域写命令按以下顺序执行，标准协议端点保留协议自身错误格式：

1. 认证 Actor，解析 Subject、Tenant、Client 和 Trace 上下文。
2. 校验 `Idempotency-Key + caller_scope + request_hash`；同键异请求返回冲突。
3. 加载聚合和全部逻辑引用，校验存在、类型、作用域和状态。
4. 执行授权、风险、保证等级、Consent、审批和安全水位检查；无法确定时按策略失败关闭。
5. 调用纯领域状态机得到新状态、原因、事件和不可逆边界。
6. 使用 `row_version = expected_version` 执行 CAS；零行更新转为并发冲突。
7. 在同一数据库事务写领域事实、Operation/Step、Outbox、Audit 和幂等结果。
8. 提交后异步发布事件；消费者使用 Inbox 和聚合版本去重、防乱序。

## 2. 状态机清单

| 聚合/过程 | 主要表 | 代码必须定义 | 关键拒绝条件 | 必测并发 |
|---|---|---|---|---|
| 用户生命周期 | `global_users` | 正式/Guest 类型、生命周期、认证锁定和安全冻结三个正交维度、Guest 到期与升级、注销冷静期、匿名化终态 | 匿名化后恢复；混用锁定/冻结状态；Guest 到期后继续签发 | 冻结与登录/改密竞争，Guest 升级与到期竞争 |
| 标识占用与绑定 | `identifiers`、`identifier_claims`、`identifier_bindings` | 规范化版本、验证、占用、解绑、隔离、释放 | 隔离期重绑；未验证标识参与找回 | 同标识双绑定只成功一个 |
| 账号合并/别名 | `operations`、`user_aliases` | 权威主体选择、冲突、补偿、墓碑 | 循环别名；终态主体复活 | 双向合并、重复提交 |
| 认证器生命周期 | `authenticators`、`credential_materials` | 登记、激活、替换、挂失、撤销 | 冻结用户登记；降级保证等级 | 替换与登录竞争 |
| 恢复码 | `recovery_code_batches`、`recovery_codes` | 批次轮换、单次消费、整体失效 | 旧批次恢复；重复消费 | 同码并发消费 |
| Challenge | `auth_challenges` | 签发、尝试计数、锁定、消费、过期 | 枚举账号；过期或跨目的消费 | 同 Token 并发消费 |
| 登录事务 | `login_transactions`、`login_transaction_steps` | 因子、Consent、风险升级、完成和过期 | 未完成签发 Session/Code/Token | 完成与过期竞争 |
| 会话 | `sessions`、`session_participants` | 空闲/绝对过期、撤销、全局退出、RP 确认 | 冻结主体刷新；过期续期 | 刷新与撤销竞争 |
| Access Token 签发 | `access_token_records` | Subject/Actor、委托链、Profile/策略/Consent/安全水位、Audience、DPoP/mTLS 确认值快照 | 缺 Actor 的代理签发；过期 Consent；SP5 无发送方约束 | 签发与冻结/Consent 撤回/委托撤销竞争 |
| OAuth 授权码 | `authorization_codes` | Client、Redirect、PKCE、单次消费 | 跨 Client/Redirect；重复消费 | Code 双换 Token |
| Grant | `authorization_grants` | Scope 上界、Consent、版本和撤销 | Pending/撤回 Consent 签发 | 授权与撤销竞争 |
| Refresh Token Family | `token_families`、`refresh_token_instances` | 轮换、序号、重放检测、家族撤销 | 使用旧实例继续换发 | 同 Refresh Token 双刷新 |
| Membership | `memberships` | 业务线/租户/组织状态正交、加入和离开 | 跨租户作用域；停用租户加入 | 邀请接受与撤回竞争 |
| Invitation | `invitations` | 目标绑定、权限上界、一次性消费、过期 | 篡改目标/作用域；接受时权限已失效 | 同邀请双接受 |
| 组织树 | `organizations` | 父子作用域、闭环、深度、移动和路径刷新 | 自引用、跨租户父节点、循环 | 并发移动同节点 |
| Consent | `consent_aggregates`、`consents` | 目的/类别/接收方、版本、撤回水位 | 范围扩大无明确同意 | 同聚合授权与撤回竞争 |
| 隐私请求 | `privacy_requests`、`legal_holds`、`deletion_proofs` | 核验、截止期、导出、删除、保留、证明 | Legal Hold 下误删；终态主体恢复 | 取消与越过不可逆边界竞争 |
| 角色授予 | 三类 `*_role_assignments` | 作用域包含、权限上界、有效期、撤销 | 自提权、跨租户、机器越环境 | 授予与撤销竞争 |
| 策略发布/决策 | `policy_versions`、`policy_bindings`、`authorization_decisions` | 编译、测试、发布、Subject/Actor/委托、上下文版本、新鲜度、有效期、默认拒绝、Obligation | 未发布策略生效；PIP 不确定放行；超出 `valid_until` 复用 | 发布切换、属性变化与缓存失效 |
| 联合身份 | `identity_providers`、`user_identities` | OIDC/SAML 稳定键、路由、防接管 | 仅凭邮箱自动合并；Transient NameID 持久化 | 同外部身份双链接 |
| 目录同步 | `directory_*` | 游标、源权威、冲突、墓碑、重试 | 旧版本覆盖新版本；跨租户映射 | 游标 CAS 与批次重试 |
| 风险评估 | `risk_signals`、`risk_assessments` | 信号规范化、模型版本、处置和解释 | 模型/策略不可用时静默放行 | 信号乱序与重复 |
| 限制与安全信号 | `security_signals`、`restriction_entries` | 命中优先级、范围、过期和解除 | 忽略有效限制；过期仍限制 | 新限制与会话刷新竞争 |
| 机器主体与凭证 | `machine_principals`、`machine_credentials` | 负责人、用途、环境、到期、轮换和失陷 | 无负责人/无到期；私钥落库 | 轮换窗口与撤销竞争 |
| 工作负载证明 | `workload_attestations`、`workload_trust_bundle_versions` | Issuer/Audience/Nonce/JTI、信任链和重放 | 未知 Trust Bundle；证明重放 | 同 Nonce/JTI 并发验证 |
| 委托 | `delegations` | Actor/Subject、权限交集、链深和撤销 | 扩权、循环、超过深度 | 撤销与 Token Exchange 竞争 |
| 审批 | `approval_cases`、`approval_actions` | 职责分离、法定人数、版本绑定、唯一 `execution_id` 单次执行 | 发起人自审；目标版本变化；重复执行标识 | 最后一票与执行竞争，双执行只能成功一次 |
| Key/JWKS | `cryptographic_keys`、`jwks_*` | 生成、激活、重叠、验证期、销毁和紧急阻断 | 未批准算法；移除仍需验证的旧 Key | 发布与签发切换 |
| 配置发布 | `configuration_*` | Schema/语义校验、Seed 漂移检测、审批、灰度、激活和回滚 | DRAFT 或未审批配置激活；秘密进入 payload；同版本内容漂移 | 双发布竞争 |
| Profile 与主联系方式 | `user_profiles`、`identifiers`、`identifier_bindings` | 主联系方式必须属于当前用户、当前有效且已验证；换绑时原子更新 Profile 版本 | 未验证、已解绑或他人 Identifier 被设为主联系方式 | 换绑与消息发送/账号恢复竞争 |
| 统一事件信封 | `outbox_events`、`event_schema_versions` | Producer 授权、Subject/Actor 标识类型、业务线、数据版本、因果链、敏感级别和对外 pairwise 改写 | 缺 Trace/Subject 类型；Webhook 暴露 Global UID；旧版本覆盖 | 同聚合并发事件排序和重复发布 |
| Webhook | `webhook_*` | 所有权、SSRF、签名、重放窗、退避和停用 | 私网/重绑定/未知 Key；跨租户事件 | 同 Delivery 重试领取 |
| 消息 | `message_*` | 抑制、限速、路由、模板变量、供应商降级 | 认证失败时绕过验证；秘密进模板 | 同幂等键重复发送 |
| 迁移 | `migration_*`、`legacy_*` | 权威切换、双写顺序、对账、回滚和退役 | 改库绕过接口；旧版本覆盖新值 | 同变更重复/乱序消费 |

## 3. 必须实现的代码构件

每个领域模块至少包含：

- `Domain`：聚合、值对象、状态 Enum、转换函数、不变量和领域事件。
- `Application`：Command/Query Handler、幂等、授权、风险、审批和事务边界。
- `Contracts`：API DTO、错误码、事件 Schema、版本与兼容策略。
- `Infrastructure`：仓储、SQL 映射、加密/KMS、Outbox/Inbox、时钟和外部适配器。
- `Tests`：状态机属性测试、并发测试、负向隔离测试、故障注入和契约测试。

状态 Enum 只存在于代码；数据库中的 `varchar` 不得成为状态全集的来源。每个状态机需要输出机器可读转换图，并测试“所有未声明转换均拒绝”。

## 4. 数据访问约束

- 所有更新 SQL 必须包含 `row_version = @expectedVersion`，并设置 `row_version = row_version + 1, updated_at = CURRENT_TIMESTAMP`。
- 不允许通用仓储绕过租户过滤；带租户对象的仓储方法必须强制接收 `TenantContext`。
- 敏感字段只在专用仓储中出现；DTO、日志、异常和事件默认不得包含密文，更不得包含解密明文。
- 追加型表只暴露 `AppendAsync`；不提供 Update/Delete 仓储方法。
- 分区事实表的逻辑引用查询必须携带时间范围，避免全分区扫描。

## 5. 事务模板

```text
BEGIN
  幂等记录占位或核验
  加载并锁定/CAS 聚合
  校验逻辑引用、租户、状态、权限、风险、审批
  写聚合与从属事实
  写 Outbox Event
  写 Audit Event（高风险操作审计不可写则失败关闭）
  完成幂等结果
COMMIT
```

跨系统操作只在本地事务提交本地事实和下一步 Outbox，不使用分布式事务；失败通过 `operations + operation_steps` 检查点继续或前向修复。

## 6. 新增存储字段的代码使用规则

- `global_users.authentication_lock_state` 与 `security_freeze_state` 必须分别求值，不允许通过时间字段推导后覆盖另一个维度；时间字段只保存截止或发生时间。
- Guest 使用同一 `global_users` 聚合和稳定 UID；升级正式账号只改变 `user_type` 并清理到期时间，若并入已有用户则走账号合并和 Alias 墓碑流程。
- 创建 `operations` 时一次性保存 `caller_scope`、幂等键、请求摘要、能力编号、Saga 类型和策略版本；后续步骤不得改写这些创建快照。
- Session、Token 和 PDP Decision 的 Profile、策略、Consent、安全水位、Actor/Delegation 都是求值结果快照；是否仍有效必须与当前权威水位比较，不能只信任快照。
- `sender_constraint_thumbprint` 只保存 DPoP JKT 或 mTLS `x5t#S256` 等确认值，不保存客户端私钥、完整证书或完整 Token。
- Outbox 核心信封字段使用独立列；`headers` 仅承载扩展路由信息，禁止重复定义或覆盖 Subject、Actor、Trace、因果和数据分类。
- 系统 Seed 只创建 DRAFT 控制面对象；代码必须通过审批与发布流程激活。重复执行 Seed 时内容摘要不一致必须阻断部署。
