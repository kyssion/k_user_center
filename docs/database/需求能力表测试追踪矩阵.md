# 需求—能力—表—代码—测试追踪矩阵

该矩阵按能力域维护实现入口。领域内每个 `CAP/REQ/INV/API/EVT/AT/SLO` 在进入代码迭代时继续拆成单条测试用例；本文件先固定数据库和模块边界，防止能力遗漏或误固化到数据库。

## 全局契约

| 规范 | 存储支撑 | 代码责任 | 主要证据 |
|---|---|---|---|
| `INV-G-001~004` | 用户/Subject/标识/外部身份唯一约束和墓碑 | ID 生成、规范化、SAML/OIDC 稳定键 | `AT-ID-*`、并发/属性测试 |
| `INV-G-005~006` | 正交状态字段、角色/策略/关系事实 | 最严格状态合并、默认拒绝、后端 PEP | `AT-TENANT-*`、`AT-AUTHZ-*` |
| `INV-G-007~008` | 摘要/密文字段、追加审计、专用权限 | 日志脱敏、审计失败关闭 | `AT-SEC-001/002`、`AT-AUDIT-*` |
| `INV-G-009~010` | 终态/别名/删除证明、Outbox | 不可恢复匿名化、同事务事件 | `AT-ID-005/016`、故障注入 |
| `INV-G-011~012` | 配置版本/发布、幂等唯一键 | 审批激活、同键同请求语义 | `AT-CTRL-*`、`AT-API-001` |
| `INV-G-013~016` | 安全水位、会话/Grant/Login Transaction | 冻结和撤销传播、完成态守卫 | `AT-SESSION-*`、`AT-AUTH-013/014` |
| `INV-G-017~018` | 审批/委托事实 | 职责分离、单次执行、权限交集 | `AT-ASR-*`、`AT-MACHINE-004` |
| `API-G-001~019` | 幂等、Operation、Step、row_version | 错误映射、分页、异步和协议边界 | `AT-API-001~005` |
| `EVT-G-001~013` | Outbox/Inbox、Schema、Webhook、Checkpoint | 至少一次、去重、改写 Subject、SSRF/验签 | `AT-EVENT-001~005` |

| PLT | `CAP-PLT-*` | `business_lines`、`applications`、`oauth_clients`、`api_resources`、`resource_quotas`、配置发布 | `Platform` | Client 上线认证、协议一致性、备份恢复、容量和租户隔离门禁 |

## 数据库验证与业务测试分工

- `database/postgresql/verification` 证明 113 张表、Comment、基础约束、分区、权限和禁止对象符合总纲。
- .NET 测试证明状态转换、逻辑关系、租户隔离、权限、风险、协议、审批、撤销、删除和故障恢复符合能力地图与蓝图。
- 数据库验证通过不能替代业务验收；业务测试不得依赖数据库 Foreign Key 或 Trigger 才成立。
