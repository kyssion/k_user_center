# 业务模型与数据库持久化边界清单

> 本文件只定义业务模型需要持久化的事实、逻辑关系和数据库应承担的硬边界，不定义具体语言、类、接口、Handler、Repository、API 路由或事务代码。进入编码阶段后，应另行生成代码实施文档；该实施文档不得反向改变本文件已经确认的业务语义和持久化事实。

## 1. 数据库文档范围

数据库文档回答以下问题：

1. 业务模型是否有足够的稳定事实支撑状态恢复、查询、审计、撤销、对账和迁移。
2. 哪些对象拥有独立生命周期，哪些只是值对象、快照、事件或逻辑关系。
3. 哪些事实必须结构化为独立字段，哪些扩展内容可以进入版本化 JSON。
4. 哪些完整性边界必须由 PostgreSQL 最终兜底。
5. 哪些规则明确不属于数据库，后续实施必须在应用层完成。

数据库文档不回答代码目录、类名、方法签名、框架用法、外部组件调用顺序和 API DTO；这些内容属于后续代码实施文档。

## 2. 持久化原则

1. 只有独立、稳定、需要查询、审计、恢复或对账的数据事实才建表或独立字段，不把代码流程步骤机械翻译成表。
2. PostgreSQL 保存状态值、版本、原因、业务时间和结果事实，但不定义状态全集、合法转换、授权条件、风险处置或审批流程。
3. PostgreSQL 不创建 Foreign Key、业务 Trigger、持久化业务 Routine、PostgreSQL Enum 或表达业务语义的 View。
4. 逻辑引用只保存标识和查询索引；目标存在性、类型、租户/业务线一致性、生命周期和权限由后续实施负责。
5. Primary Key、Unique、NOT NULL、数据类型、长度、行内基础 Check、`row_version`、必要原子消费和数据库权限属于数据库硬边界。
6. 唯一性和 CAS 不得只依赖“先查询再写入”的应用判断，数据库必须作为并发竞争的最终裁决者。
7. JSONB 只承载版本化配置、协议扩展、快照、证据和低频扩展属性；高频过滤、唯一性、逻辑关系、安全水位和生命周期字段必须独立建模。
8. `operations + operation_steps` 只保存跨事务流程的权威状态、检查点、结果和证据，不在数据库中建设工作流引擎。
9. Outbox、Audit Outbox、幂等结果与权威事实需要同事务持久化，但事件生成、投递、补偿和重试语义不在数据库中实现。
10. 敏感原文不落库；数据库只保存密文、摘要、盲索引、公开材料和 KMS/HSM 引用。
11. 追加事实和不可变版本通过权限、只追加写入接口和审计共同保护；发布新版本，不原地改写历史内容。
12. 数据库对象的存在不代表当前阶段必须实现全部业务能力；建设阶段由能力与实施计划决定，数据库模型保持目标态语义一致。

## 3. 业务模型持久化检查

| 业务模型/过程 | 主要持久化载体 | 必须保存的事实 | 数据库硬边界 | 非数据库职责与后续关注 |
|---|---|---|---|---|
| 用户主体 | `global_users` | 稳定 UID、用户类型、生命周期、认证锁定、安全冻结、安全水位、版本和业务时间 | UID 唯一、版本/epoch 非负、CAS 字段 | 三个状态维度的合法转换、冻结影响面、Guest 升级和终态规则 |
| Subject | `user_subjects` | User、Client、Subject、生成版本 | Client 内 Subject 唯一 | Pairwise 生成、轮换和对外暴露规则 |
| Identifier | `identifiers`、`identifier_claims`、`identifier_bindings` | 规范化版本、盲索引、验证、占用、绑定、解绑、隔离和原因 | 作用域内唯一占用、版本字段 | 规范化、验证、换绑、隔离期、租户一致性和并发命令 |
| 外部身份 | `user_identities` | 协议、Issuer/Entity ID、稳定外部键摘要、用户关联和元数据 | 稳定外部键唯一 | OIDC/SAML 键计算、防接管和禁止仅凭邮箱合并 |
| 账号合并 | `operations`、`operation_steps`、`user_aliases` | 权威主体、Alias 墓碑、步骤检查点、结果和失败证据 | Alias 唯一、Operation 幂等键 | 冲突处理、补偿、不可逆边界和下游迁移 |
| 用户资料 | `user_profiles`、`profile_documents` | 公共资料版本、主联系方式引用、作用域化文档和 Schema 版本 | 用户 Profile 唯一、文档命名空间唯一 | 字段权威、可见性、净化、Schema 校验和脱敏 |
| 认证器 | `authenticators`、`credential_materials`、`password_history` | 类型、状态、保证特征、材料版本、摘要/密文/公开材料和使用时间 | 材料唯一、至少存在一种材料、版本有效 | 登记、验证、替换、撤销、密码哈希和 AAL 计算 |
| 恢复码 | `recovery_code_batches`、`recovery_codes` | 批次、序号、摘要、状态、过期和消费时间 | 批次内序号唯一、Token 摘要唯一 | 批次轮换、单次消费和旧批次失效 |
| Challenge | `auth_challenges` | 用途、Client、主体/目标、Token 摘要、状态、尝试次数、版本化上下文、过期和消费时间 | Token 摘要唯一、尝试与有效期基础约束、CAS | 上下文 Schema、原事务绑定、验证、防枚举、重发和原子消费 |
| 登录事务 | `login_transactions`、`login_transaction_steps` | 原授权上下文、已完成步骤、风险快照、状态、过期和版本 | 事务步骤唯一、有效期和 CAS | 因子编排、Consent、Step-up、完成条件和禁止未完成签发 |
| 认证上下文和尝试 | `authentication_contexts`、`authentication_attempts` | AAL/acr/amr、策略版本、证据摘要、结果、原因和时延 | 尝试记录追加、版本有效 | 认证决策、失败收敛、保证等级和风险解释 |
| Client 与资源 | `oauth_clients`、`api_resources`、`oauth_scopes` | Owner、环境、Profile、配置、安全水位、状态和有效期 | Client ID/Audience/Scope 唯一、CAS | 协议校验、Profile 接入认证、Scope 上界和下线流程 |
| 授权码 | `authorization_codes` | Code 摘要、Client、Redirect、PKCE、Scope、状态和过期 | 摘要唯一、有效期、CAS | 单次兑换、重放处置和上下文匹配 |

| Refresh Token | `token_families`、`refresh_token_instances` | Family 状态、序号、Token 摘要、签发/使用/过期和轮换结果 | Token 摘要唯一、Family 序号唯一、CAS | 原子轮换、丢包重试识别、重放和家族级撤销 |
| Access Token | `access_token_records` | Token 摘要/JTI、Subject/Actor、委托、Profile、策略、Consent、安全水位、Audience、确认值和有效期 | JTI/摘要唯一、有效期基础约束 | Token 生成、签名、声明最小化、撤销和资源服务器校验 |
| 撤销 | `revocation_entries` | 目标、原因、生效时间、水位和过期 | 水位非负、逻辑唯一性和索引 | 撤销范围计算、传播、失败关闭和 SLO |
| Tenant 与组织 | `business_lines`、`tenants`、`tenant_domains`、`organizations` | Owner、状态、安全水位、域名、父组织和版本 | Code/Domain 唯一、禁止自引用、CAS | 租户隔离、组织树防环、停用影响和所有权转移 |
| Membership、邀请和组 | `memberships`、`invitations`、`groups`、`group_members` | 成员作用域/状态、邀请目标/权限上界、组关系和有效期 | 关系唯一、邀请有效期、CAS | 邀请单次消费、角色上界、跨租户拒绝和成员生命周期 |
| Consent 与协议 | `agreement_versions`、`agreement_acceptances`、`consent_aggregates`、`consents` | 协议版本、接受证据、目的/类别/接收方、Consent Epoch、授予/撤回事实 | 版本唯一、接受证据追加、epoch 非负 | 合法依据、单独同意、撤回传播和 Grant/订阅联动 |
| 隐私请求 | `privacy_requests`、`legal_holds`、`data_export_artifacts`、`deletion_proofs` | 请求状态、截止期、保留阻断、导出物、删除结果和证明 | 截止期/有效期基础约束、删除证明追加 | 身份核验、导出、删除编排、Legal Hold 和下游对账 |
| 角色与策略 | `permissions`、`roles`、`*_role_assignments`、`data_scope_definitions`、`policy_versions`、`policy_bindings` | 权限目录、角色、授予范围/期限、不可变策略版本、绑定和版本 | Code/版本/绑定唯一、有效期和 CAS | 权限上界、职责分离、策略编译、发布和默认拒绝 |
| 授权决策 | `authorization_decisions` | Subject/Actor、输入摘要、策略/上下文版本、结果、原因、Obligation 和有效期 | 决策 ID 唯一、追加写、有效期基础约束 | PDP/PIP 求值、缓存新鲜度、列表前过滤和失败关闭 |
| 联邦和目录同步 | `identity_providers`、`directory_connectors`、`directory_sync_*`、`directory_object_mappings` | IdP/Connector 配置引用、游标、批次结果、外部对象映射和源版本 | Issuer/外部映射唯一、游标 CAS | 协议处理、属性映射、源权威、冲突、墓碑和重试 |

| 机器主体与凭证 | `machine_principals`、`machine_credentials` | Owner、用途、环境、状态、安全水位、凭证类型、指纹、有效期和替代链 | 指纹唯一、一个旧凭证最多被一个新凭证替代、有效期和 CAS | Client 认证、轮换、重叠窗口、失陷和最小权限 |

| 迁移 | `legacy_systems`、`legacy_id_mappings`、`migration_batches`、`migration_items`、`migration_change_logs` | 旧系统权威范围、ID 映射、批次/对象状态、检查点和不可变变更日志 | 外部映射唯一、序号/幂等键唯一、变更追加 | 清洗、冲突、双写、切换、回滚、对账和退役 |

## 4. 模型变更判定

新增业务要求时，按以下顺序判断是否需要调整数据库：

1. 是否产生新的独立生命周期对象或需要长期审计的事实；若否，优先扩展现有模型。
2. 是否需要按该值高频过滤、唯一约束、建立逻辑关系或执行安全水位判断；若是，使用独立字段，不隐藏在 JSONB。
3. 是否只是可重算决策、中间计算结果或代码流程；若是，不建立永久表。
4. 是否跨越同步事务边界并需要恢复；若是，复用 `operations + operation_steps`。
5. 是否是历史版本；若是，新增不可变版本，不原地改写已发布内容。
6. 是否需要数据库最终解决并发竞争；只有唯一性、CAS、单次消费和必要原子写入进入数据库硬边界，其余业务判断留给后续实施。

## 5. 与后续代码实施文档的关系

进入代码阶段后，应基于本文件另行生成实施文档，补充命令、接口、类、事务步骤、外部依赖、错误码和测试。实施文档可以选择实现方式，但必须满足以下约束：

- 不新增与本文件重复的权威事实。
- 不绕过数据库唯一性、CAS、权限和追加写边界。
- 不把状态机、授权、风险、审批或跨系统工作流下沉为数据库 Trigger/Routine。
- 发现业务模型无法表达需求时，先回到数据库模型评审，不通过临时 JSON 字段或影子表规避。
