# ADR-0001：逻辑关系与外键策略

- 状态：`PROVISIONAL`
- 决策域：数据库完整性与可迁移性
- 冻结门禁：算法与密码合规关闭、真实 PostgreSQL 验证、215 个逻辑引用完成分类

## 背景

当前候选 SQL 不创建 Foreign Key，并通过字段 Comment、逻辑关系索引、应用写入前校验和孤儿扫描维护关系。该方式避免把租户、状态、权限和删除编排错误地下沉为数据库规则，但也会把纯结构存在性完整性全部转移到代码。

业务授权和状态机不属于 Foreign Key 能力范围；“不能用 FK 表达业务规则”不等于“所有结构关系都不应使用 FK”。因此无 Foreign Key 只能作为候选策略，不能在逐关系评审前视为最终冻结结论。

## 暂定决策

1. 当前 Migration 保持无 Foreign Key，避免在关系分类完成前产生大范围 DDL 变更。
2. 每个逻辑引用必须归入以下一种类型：
   - `STRUCTURAL`：同权威域、稳定目标、父对象不得早于子对象清理；最终冻结时必须评估 FK。
   - `CROSS_DOMAIN`：跨权威域、生命周期独立；默认使用逻辑引用。
   - `POLYMORPHIC`：目标由类型注册表解析；禁止 FK。
   - `HISTORICAL`：主对象清理后仍需保留审计、墓碑或证据；禁止级联 FK。
   - `PARTITIONED_GLOBAL_ID`：受分区唯一性限制；由高熵 ID、幂等和代码检查保证。
3. 不论是否使用 FK，最终用户/管理员授权、Tenant/Business Line 作用域、状态、Owner、风险和审批均由代码校验。
4. 禁止 `ON DELETE CASCADE` 承载业务删除。所有物理清理仍使用受审批维护流程。

## 最终冻结所需证据

- 215 个逻辑引用均登记关系类型、是否必填、租户守卫、删除行为、锁/CAS 策略和校验 Owner。
- `STRUCTURAL` 关系逐项记录采用或拒绝 FK 的理由。
- 并发插入、父对象终态、匿名化、迁移和维护清理负向测试通过。
- 真实 PostgreSQL 孤儿检查、执行计划和维护窗口验证通过。

在这些证据完成前，数据库文档只能称为候选基线。
