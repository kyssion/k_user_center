# ADR-0003：.NET 10、SqlSugar 与 PostgreSQL 工程技术基线

- 状态：`ACCEPTED`
- 日期：2026-08-07
- 决策范围：阶段 0 工程骨架、数据访问组件和项目目录
- 实施细节：[阶段 0 技术方案与工程结构](../代码实施/阶段0技术方案与工程结构.md)

## 背景

项目已经确定使用 .NET 10、SqlSugar 和 PostgreSQL。当前仓库仍是单一 WeatherForecast 模板项目，并同时引用 `Microsoft.AspNetCore.OpenApi 10.0.9` 与不兼容的 `Microsoft.OpenApi 3.9.0`；SDK、依赖版本、模块目录、数据访问生命周期和测试门禁尚未冻结。

数据库已经存在版本化 PostgreSQL SQL，因此 ORM 不能成为第二套 Schema 权威，也不能在运行时自动建表或修改结构。

## 决策

1. 所有生产项目和测试项目使用 `net10.0`，SDK 补丁版本通过 `global.json` 固定。
2. 所有 C# 项目和测试位于仓库内层 `k_user_center/`；解决方案级构建配置保留在仓库根目录。
3. 采用模块化单体和独立程序集边界，Host、BuildingBlocks、SqlSugar Persistence 与模块 Contracts/Domain/Application/Infrastructure 分离。
4. 采用 `SqlSugarCoreNoDrive` 并显式引用 Npgsql，避免完整 SqlSugar 包锁定旧 PostgreSQL 驱动；具体版本由集中包管理和锁文件固定。
5. SqlSugar 使用 scoped Client；事务由 Application 命令边界控制，同事务包含权威事实、Outbox、本地审计、审计投递 Outbox 和幂等结果。
6. `database/postgresql` 继续是数据库 Schema、Migration、Seed、角色和权限的唯一可执行权威来源；禁止 SqlSugar CodeFirst 和运行时 Schema 同步。
7. 数据库实跑、类型映射和 SqlSugar/Npgsql 兼容性由用户手工验证；在证据形成前不能宣称数据库集成验收通过。

## 理由

- 独立程序集可用编译和架构测试阻断 Domain/Application 对 ORM、HTTP 和模块 Infrastructure 的错误依赖。
- NoDrive 包允许项目显式控制 PostgreSQL 驱动版本，降低旧驱动被传递锁定的风险。
- scoped Client 将连接/事务状态限制在单个命令作用域，避免跨请求共享可变事务状态。
- 保留 SQL Migration 权威可避免文档、ORM CodeFirst 与生产数据库形成三套互相漂移的定义。

## 后果

正面影响：

- 构建、包版本和依赖方向可重复验证；
- 数据库访问可替换且不污染 Domain；
- 事务、日志、健康检查和异常映射形成统一入口；
- 所有代码集中在用户指定的 `k_user_center/` 目录。

成本与风险：

- 项目数量增加，需要维护程序集引用和锁文件；
- SqlSugarCoreNoDrive 与 Npgsql 10 的真实运行兼容性必须验证；
- SqlSugar 的传递依赖仍需 NuGet Audit，不能因为使用 NoDrive 就视为最小依赖；
- 目标 PostgreSQL 主版本尚未登记，数据库验收不能关闭。

## 验证条件

1. Release restore/build/test/format 全部通过且无未接受的 High/Critical 漏洞。
2. 架构测试能够阻断 Domain/Application 引用 SqlSugar、Npgsql、ASP.NET 或其他模块 Infrastructure。
3. 用户手工完成 PostgreSQL Migration/Verification、事务、CAS、类型映射和错误映射验证。
4. 真实代码目录与技术方案一致，仓库根目录不存在应用源码 `src/` 或 `tests/`。

若 NoDrive + Npgsql 组合无法通过数据库验证，必须新增 ADR 取代本决策中的驱动组合，不得静默退回旧版 Npgsql 或启用 CodeFirst。
