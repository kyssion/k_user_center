# 代码实施契约索引

本目录把能力地图、验收蓝图和数据库持久化边界展开为代码必须实现的命令、事务、并发、幂等、事件和错误契约。领域契约本身不绑定 Controller、Handler、Repository、ORM 或消息组件；已经批准或待评审的工程选型单独记录在技术方案和 ADR 中，不能反向放宽领域契约。

数据库只负责事实持久化、PK/Unique/NOT NULL、稳定的基础行内 Check、CAS 字段、技术时间、索引、分区和部署身份的粗粒度隔离。参数与 Schema 校验、逻辑引用、状态转换、最终用户/管理员权限、租户与数据范围、领域 Owner、风险、审批、协议语义、重试、补偿和删除编排均由用户中心代码负责。

## 开始编码前门禁

每个进入迭代的命令必须明确：

1. 对应 `CAP/REQ/INV/API/EVT/AT` 编号。
2. 调用者、主体和 Tenant/Client/Business Line 作用域。
3. 参数格式、Schema、Allowlist、前置条件和失败关闭规则。
4. 最终用户/管理员权限、数据范围、领域 Owner、风险和审批判断。
5. 读取表、写入表、逻辑引用校验、事务边界和锁/CAS 条件。
6. 唯一、NOT NULL、基础 Check、并发和持久化异常的稳定错误映射。
7. 幂等键作用域、请求摘要及同键不同请求处理。
8. 与权威事实同事务写入的领域 Outbox、本地 `audit_events`、审计投递 Outbox 和幂等结果。
9. 外部调用位置、重试、补偿、不可逆边界和人工接管条件。
10. 正向、参数非法、越权、跨租户、并发、重放、过期和故障注入测试。
11. 使用的错误码和 Operation reason code 已存在于错误码注册表，涉及的状态字段已存在于状态机注册表。
12. 适用威胁已绑定 `THR-*`，安全控制和负向测试可追踪。

数据库角色只代表部署身份，不能作为业务授权已经通过的证据。禁止仅凭“由代码负责”开始实现，也禁止把同一套业务权限或状态机同时放入代码和数据库。

## 实施追踪矩阵维护

[`实施追踪矩阵.csv`](./实施追踪矩阵.csv) 是当前实现与验收覆盖的唯一权威清单。数据库持久化覆盖索引、能力地图验收表和领域命令概要不能替代它。

矩阵目前只有表头，表示尚无生产业务命令通过迭代入口门禁。不得添加虚构 Owner、Phase、测试或证据来消除空表状态；实际 Owner、阶段和首个垂直切片批准前，阶段 1a 保持 NO-GO。

填写规则：

1. 一条规范性需求一行；同一需求跨多个独立能力或阶段时拆行。
2. `requirement_id` 必须是已发布的 `REQ/API/EVT`；只有能力编号时先补规范编号。
3. `capability_id` 必须存在于能力地图，Phase 不得早于其依赖门禁。
4. `owner` 必须是实际团队或明确兼任方，不能填写“待确认”。
5. `test_ids` 只能引用已经存在的测试；计划测试不是验收证据。
6. `evidence_uri` 必须是仓库、流水线、报告或受控证据系统中的稳定位置。
7. 例外填写 `exception_id` 并关联风险接受人、补偿控制和到期日。

CI 应阻断：矩阵为空却提交生产 Handler、协议端点或 Migration；当前阶段 MUST/P0 缺行；Owner、Phase、测试、SLO 或引用不存在；Evidence 不可用；Exception 已过期。第一批行只覆盖已批准的首个垂直切片，不批量生成虚假绑定。
