# 模块边界与依赖规则

> 状态：阶段 0 结构基线。具体项目路径由 `R0-004` 实现，但依赖方向和跨域访问规则不得由实现自行改变。

## 模块结构

每个能力域模块内部按以下方向依赖：

```text
Contracts → Application → Domain
Infrastructure → Application/Domain ports
Host → Contracts/Application/Infrastructure composition
```

- Domain 不依赖数据库、消息、HTTP、缓存、KMS 或其他模块的 Infrastructure。
- Application 只通过端口访问基础设施，通过公开命令或查询契约访问其他模块。
- Infrastructure 不得被其他模块直接引用。
- Host 只负责组合、协议适配、中间件和部署，不承载领域状态机。

## 跨模块规则

| 调用类型 | 允许方式 | 禁止方式 |
|---|---|---|
| 同步命令 | 目标模块公开 Application Contract | 直接调用目标 Repository 或修改目标表 |
| 同步查询 | 目标模块公开 Query Contract 或经批准只读投影 | 绕过 Tenant/Owner/数据范围守卫 |
| 异步传播 | 标准 Outbox/Event Schema | 同步双写多个权威域 |
| 长流程 | `operations + operation_steps`，每个实例一个业务 Owner | 每个参与域各自推进一套 Operation 状态 |
| 共享事实 | 按业务模型边界清单的唯一权威域维护 | 影子状态、未声明双写、跨模块 Save(Entity) |

## 必须由架构测试阻断

1. 模块直接引用其他模块的 Infrastructure 或数据访问实现。
2. Controller、Worker 或消息消费者绕过 Application/PEP 直接访问 Repository。
3. 非权威域更新共享表的生命周期字段。
4. Domain 引用具体 ORM、消息客户端、缓存客户端或系统时钟。
5. 业务模块自行实现 OAuth/OIDC、密码学原语或未登记错误语义。

实际目录、程序集和依赖测试完成前，阶段 1a 仍为 NO-GO。
