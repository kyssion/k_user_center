# 全局持久化与事务规范

## 1. 单条命令执行骨架

所有改变权威事实的同步命令按以下顺序实现：

1. 在事务外完成语法、长度、协议格式、JSON Schema、算法和枚举 Allowlist 等不依赖权威状态的参数校验。
2. 解析调用者、主体、Tenant、Client、Business Line、安全 Profile 和数据范围；缺少或歧义时默认拒绝。
3. 在代码中完成认证强度、最终用户/管理员授权、领域 Owner、风险、审批和限流判断；需要稳定快照的版本 ID 随命令持久化。
4. 开启数据库事务，按幂等作用域登记 `idempotency_records`；同键不同 `request_hash` 返回冲突。
5. 读取并校验所有逻辑引用的目标、作用域、生命周期和版本；存在不代表状态、租户或权限有效。并发敏感目标使用行锁或版本快照，避免“检查后状态已变化”。
6. 执行业务前置条件和合法状态转换判断。
7. 对含 `row_version` 的聚合使用 `WHERE id = @id AND row_version = @expected`，并在 SQL 中显式设置 `row_version = row_version + 1, updated_at = CURRENT_TIMESTAMP`。
8. 在同一事务写入权威事实、Outbox、Audit 和最终幂等结果；任何一项失败都回滚。
9. 提交后再执行非事务外部调用；需要可靠恢复的调用由 Outbox 或 `operations + operation_steps` 驱动。

禁止用 Trigger、Function、Stored Procedure、RLS Policy 或数据库账号体系实现第 2、3、5、6、8 步的业务判断。

## 2. 数据库边界与代码边界

| 数据库承担 | 代码必须承担 |
|---|---|
| Primary Key、Unique、NOT NULL、稳定的基础行内 Check | 参数格式、JSON 内部 Schema、Allowlist、协议条件和业务数值范围 |
| `row_version >= 0`、技术时间默认值 | expected version、CAS 更新、冲突响应、重读和有限重试 |
| 逻辑引用 ID、字段 Comment、查询索引 | 目标存在、类型解析、租户/业务线一致性、状态、Owner、删除影响和生命周期 |
| 当前 Subject/Membership 的技术占位唯一性 | 是否允许轮换、离开、重新加入及何时释放当前占位 |
| 高熵公开 ID 的查询索引 | 跨时间分区的全局唯一生成、幂等防重和重复检测 |
| 审计、敏感表和运行队列的粗粒度技术角色 | 最终用户/管理员授权、数据范围、字段可见性和命令级写入白名单 |
| 禁止运行时角色 `DELETE` | 状态终止、匿名化、Legal Hold、保留期和物理清理编排 |

数据库不创建 Foreign Key。代码必须在写入前验证逻辑引用，并在删除、匿名化、合并、轮换和迁移前执行反向影响检查；数据库孤儿扫描是事后门禁，不是写入授权机制。

JSON 顶层形状仅在长期稳定且与业务语义无关时允许基础 Check。配置、策略、事件、模板、Operation 结果和资料文档必须按类型与版本在代码中校验，不能用通用数据库 Check 推断内部 Schema。

技术时间 `created_at/updated_at/recorded_at/received_at` 使用数据库时间。业务事实时间 `occurred_at/requested_at/issued_at/granted_at` 由代码使用统一时钟显式传入；不能用数据库插入时间替代业务发生时间。

## 3. 权限边界

- `iam_app_rw`、`iam_sensitive_rw`、`iam_audit_writer`、`iam_ops` 等只表示进程技术职责，不映射用户、管理员、Tenant、角色或数据范围。
- 每个命令必须先经过用户中心 PEP 和领域服务；数据库连接具备写权限不表示调用者有权写入。
- 普通业务命令使用 `iam_app_rw + iam_audit_writer`；需要读取敏感摘要的 AUTH/OAP 命令再组合 `iam_sensitive_rw`；Worker 使用 `iam_ops`，确需密文时才组合敏感角色。
- 所有运行时角色均无 `DELETE`。物理删除和分区退役只能由单独审批的版本化迁移或维护身份执行。
- 基线不依赖 RLS、按租户建账号/Schema、`SECURITY DEFINER` 或存储过程承载业务授权；新增数据库防御纵深必须保留等价代码契约和可迁移降级路径。

## 4. 字段可变性

字段分为四类：

1. 永久不可变：内部主键、公开稳定 ID、唯一业务键、请求/内容摘要、创建/签发/记录时间和不可变版本载荷。
2. 追加式事实：Audit、认证尝试、授权决策、风险信号、审批动作、投递尝试和迁移变更日志，只允许命令代码 INSERT。
3. 生命周期元数据：状态、原因、消费/撤销/退役时间、重试计数、当前指针和 `row_version`，只允许显式字段白名单更新。
4. 可版本化内容：策略、配置、模板、Schema、密钥发布和 Subject 分配通过新增版本或新行表达，不原地改写已发布事实。

仓储不得提供无字段边界的“保存整个实体”或通用 JSON Patch。INSERT 显式列出业务字段，UPDATE 同时包含调用者作用域守卫、合法前态、expected version 和允许变化字段。

## 5. 并发、幂等与单次消费

- 聚合 CAS 受影响行数为 0 时返回 `412 VERSION_MISMATCH` 或命令定义的并发冲突，不得盲目覆盖。
- 唯一占用、当前占位、幂等键、Token 摘要和 Outbox/Inbox 唯一键由数据库裁决同一表或同一分区契约内的竞争。
- 跨 Range 分区的 `jti`、`decision_id`、`signal_id`、`delivery_id`、`request_id` 等全局唯一性由高熵生成器、幂等记录和代码重复检测保证；索引只负责定位。
- Challenge、恢复码、授权码和 Refresh Token 使用条件更新完成单次消费，同时匹配摘要、状态、过期时间和 expected version。
- 可自动重试的只有序列化失败、死锁和明确无外部副作用的 CAS 重读；业务冲突和权限失败不自动重试。

## 6. Outbox、Audit 与 Operation

- 同步命令：权威事实、Outbox、Audit 和幂等结果同事务提交。
- 跨系统长流程：事务内创建 `operations`、初始 `operation_steps` 和 Outbox，事务外由 Worker 推进。
- Operation 的请求摘要、Actor、Subject、能力编号、策略版本和作用域是创建时快照，重试不得改写。
- Worker 只更新状态、检查点、尝试次数、结果、错误和下一次重试时间。
- 越过不可逆边界前必须重新验证权限、审批、Legal Hold、幂等和补偿能力，并写入不可逆时间和审计证据。

## 7. 统一错误映射

| 场景 | API/领域结果 |
|---|---|
| 参数或 Schema 非法 | `422 INVALID_ARGUMENT`；不把数据库错误作为正常参数校验器 |
| 唯一键被占用 | `409 CONFLICT`；按约束名映射稳定领域码，不回显占用主体 |
| 同幂等键不同请求摘要 | `409 IDEMPOTENCY_KEY_REUSED` |
| expected version 不一致 | `412 VERSION_MISMATCH` |
| 逻辑引用不存在 | `404` 或 `422 INVALID_REFERENCE`，由资源暴露策略决定 |
| 引用存在但跨租户或无权访问 | 按防枚举策略返回 `404` 或 `403` |
| 基础 Check/NOT NULL 失败 | 记录约束或字段名并返回稳定内部错误；不回显敏感值 |
| 状态转换不合法 | `409 INVALID_STATE_TRANSITION` |
| 需要 Step-up/审批 | `403 STEP_UP_REQUIRED` 或 `202` + `operation_id` |
| 权威数据库不可用且操作安全敏感 | 失败关闭，不使用陈旧授权、风险或引用状态继续写入 |

## 8. 查询与索引契约

每个高频或安全关键查询必须登记到 [查询与索引契约](../database/查询与索引契约.md)，至少包含：

```text
query_id
owner_domain
table
where_predicate
order_by
expected_cardinality
required_index
tenant_guard
freshness_requirement
```

索引命中不表示业务条件已满足。代码不得为了复用索引而省略 Tenant、Owner、状态、过期时间或数据范围条件；Worker 领取必须使用原子状态/CAS 更新。
