# 实施追踪矩阵维护规则

[`实施追踪矩阵.csv`](./实施追踪矩阵.csv) 是当前实现与验收覆盖的唯一权威清单。数据库持久化覆盖索引、能力地图验收表和领域命令概要均不能替代它。

## 当前状态

矩阵目前只有表头，表示尚无生产业务命令通过迭代入口门禁。不得添加虚构 Owner、Phase、测试或证据来消除空表状态；实际项目 Owner、阶段和首个垂直切片批准前，阶段 1a 保持 NO-GO。

## 填写规则

1. 一条规范性需求一行；同一需求跨多个独立能力或阶段时拆成多行并使用不同 Evidence URI。
2. `requirement_id` 必须是已发布的 `REQ/API/EVT` 编号；只有能力级规格卡时，先在蓝图补充规范编号。
3. `capability_id` 必须存在于能力地图，且 Phase 不得早于能力依赖的技术与治理门禁。
4. `owner` 必须是项目实际存在的团队或明确登记的兼任方，不能填写“待确认”。
5. `test_ids` 引用的测试必须已经存在；计划中的测试不能作为验收证据。
6. `evidence_uri` 指向仓库、流水线、报告或受控证据系统中的稳定位置，不能填写会议纪要标题。
7. 例外必须填写 `exception_id`，并能关联风险接受人、补偿控制和到期日；空值表示没有例外。

## CI 阻断条件

- 矩阵为空但尝试提交生产业务 Handler、协议端点或 Migration。
- 当前阶段适用的 MUST 或 P0 能力缺行。
- Owner、Phase、测试、SLO 或引用编号不存在。
- Evidence URI 为空、不可访问或最近一次验证失败。
- Exception 已过期。

第一批行应只覆盖通过评审的首个垂直切片，不应为追求“全量有行”而批量生成虚假绑定。
