# 代码实施就绪审计

> 审计日期：2026-08-06  
> 当前结论：**允许进入阶段 0 整改与工程骨架建设；阶段 0 出口未通过；阶段 1a 业务实施 NO-GO**  
> 判断范围：仓库内能力地图、建设与验收蓝图、数据库设计与 SQL、代码实施契约、当前 .NET 工程和本地可验证工具链。

## 1. 判断

当前文档已经足以约束稳定的数据事实、领域边界、数据库职责、主要状态机、通用 API/事件原则和阶段 0 的目标，因此可以开始：

- 修复并固化可重复构建；
- 冻结技术选型并形成 ADR；
- 搭建模块化单体骨架和公共基础设施；
- 建设本地依赖、数据库实跑和 CI 门禁；
- 为阶段 1a 候选能力展开逐条矩阵和命令规格卡，但暂不实现生产业务命令；
- 使用测试夹具或内部技术探针验证事务、CAS、幂等、Outbox/Audit，不把探针作为业务能力交付。

当前文档和工程尚不足以支持阶段 1a 全量业务代码并行开发。禁止仅凭领域级概要直接实现认证、Token、密钥、租户、授权、隐私等模块。

依据：

- [能力地图 §11.0](../能力地图.md#110-技术基线与工程骨架)明确规定技术基线未冻结前阶段 1a 不得开工。
- [建设与验收蓝图 §18.4](../统一身份与访问平台建设与验收蓝图.md#184-需求到证据追踪矩阵)规定只有领域级模糊映射的能力不得开始实现。
- [代码实施契约索引](../implementation/README.md#开始编码前门禁)要求每个进入迭代的命令先明确十类实施契约。

## 3. 允许与禁止的开工范围

### 允许立即开始

1. 修复依赖并恢复构建。
2. 固定 SDK、包管理、静态分析和构建规则。
3. 建立模块化单体目录、依赖方向和跨模块访问检查。
4. 建立健康检查、配置、结构化日志、追踪、错误中间件和可信时钟抽象。
5. 建立数据库连接、事务执行器、CAS、幂等、Outbox/Audit 和 Migration 测试基座。
6. 建立本地依赖编排和 CI 基础门禁。
7. 完成技术 ADR、Owner、Phase、算法合规与 SLO 决策。
8. 为阶段 1a 的第一个候选垂直切片填写实施矩阵和命令规格卡，但不提前实现生产业务命令。

### 当前禁止开始

1. 自研 OAuth/OIDC 协议实现。
2. 在授权服务器未选型前实现最终 Token/Grant/Logout/JWKS 流程。
3. 在算法合规未关闭前冻结密码哈希、签名算法和密码模块实现。
4. 在命令规格卡未绑定需求、权限、事务、事件和测试前批量创建 Handler/Repository。
5. 多团队并行实现全部领域，事后再补 Owner、矩阵和状态机测试。
6. 把数据库技术角色、前端控制或不可枚举 ID 当作业务授权。
7. 把阶段 0 的技术探针或最小协议链路当成阶段 1a 业务能力已经交付。
