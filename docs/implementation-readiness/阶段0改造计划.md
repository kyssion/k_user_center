# 阶段 0 改造计划

## 1. 执行原则

- 先恢复构建，再冻结技术决策，再建设基础设施，最后进入业务垂直切片。
- 不要求先展开全部目标态需求；但任何进入当前迭代的能力必须先完成逐条矩阵和命令规格卡。
- 算法合规未关闭时，可以建设不绑定算法的端口、测试替身和基础设施骨架，不得冻结生产密码实现。
- 每项完成必须留下仓库内证据；会议结论或口头确认不算完成。

## 3. 推荐顺序

```text
R0-001 构建恢复
  ├─ R0-002 SDK/包策略
  ├─ R0-003 测试骨架
  └─ R0-004 模块结构

R0-005/006/007 技术 ADR ─┐
R0-011/012/013 治理决策 ─┼─ R0-014 实施矩阵 ─ R0-015/016 首个候选切片规格
R0-008/009/010 工具链 ───┘                         │
                                                     ├─ R0-017 持久化技术探针
                                                     └─ R0-018 最小登录链路
```

其中 `R0-005`、`R0-012` 是认证和 Token 最终实现的硬依赖；其他非密码基础设施可以并行推进。

## 4. 阶段 1a 开工门禁

以下项目必须全部满足，才允许将状态从 `NO-GO` 改为 `GO`：

- [ ] `dotnet restore/build/test` 在干净环境通过。
- [ ] SDK 与关键包版本已固定，无已接受范围外的高危漏洞。
- [ ] 授权服务器及关键依赖 ADR 已批准。
- [ ] PostgreSQL 全链路实跑及 Verification 通过。
- [ ] 本地环境一条命令可启动。
- [ ] CI 至少包含构建、测试、数据库契约和敏感信息扫描。
- [ ] 当前迭代所有能力均有实际 Owner 和 Phase。
- [ ] 算法/密码合规、AAL 映射和当前切片适用 SLO 已关闭。
- [ ] 当前迭代矩阵行完整且引用的需求、事件和测试真实存在。
- [ ] 当前迭代每个命令的规格卡通过评审。
- [ ] 最小登录链路使用选定组件跑通，而不是临时自研协议代码。

## 5. 阶段 0 技术探针与阶段 1a 首个切片

阶段 0 使用测试夹具或内部技术探针验证以下工程能力，探针不得暴露为生产 API、不得写入正式实施矩阵的业务交付证据：

- 输入验证与稳定错误信封；
- 测试 Actor、Tenant/Business Line 上下文传播；
- UUIDv7/公开 ID 生成器；
- `idempotency_records +` 测试夹具表 `+ outbox_events + audit_events` 同事务；
- 重复幂等键、唯一冲突、数据库失败和审计失败关闭测试；
- 内部契约 Schema 与测试证据。

阶段 0 出口门禁全部通过后，阶段 1a 的第一个生产业务切片可优先选择 `CreateGlobalUser + Idempotency + Outbox + Audit`。授权码登录、密码、验证码、Token 和 JWKS 还必须等待授权服务器、算法合规、短期秘密存储与消息通道决策关闭。
